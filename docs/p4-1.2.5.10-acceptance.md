# P4-1.2.5.10 — Dynamic Pool acceptance coverage and remaining integration

Automated coverage includes:
- BMPOOL03 format/reopen, CRC validation and reserved-region format refusal.
- Uncommitted after-image ignored after injected Commit write failure.
- Uncertain Commit Sync outcome recovered by reopen.
- Committed Extent Map corruption fails closed.
- Stale writer rejected after another writer advances Generation.
- Owner lease loss before Commit prevents publication; OwnerEpoch persists and advances.
- Device growth persists as Free extents only; Metadata does not grow automatically.
- Multipath/single-path/local devices share the Device interface; logical sector mismatch is rejected.
- Same-parent bounded Metadata extent views and fragmented DataView offset translation.
- BMPOOL02 format recognition and write refusal.
- bmctl Owner lease helper lifetime/epoch contract tests.

GitHub Actions runs Go tests, race tests, vet and Linux 5.15 DM/kernel build. Tests use sparse regular-file devices and injected I/O faults. They are not a substitute for two-node SAN power-loss testing, multipath path-failure injection, SCSI PR PREEMPT AND ABORT verification, or sanlock/OwnerCoordinator takeover testing.

Remaining production integration:
1. The configured bmctl Owner lease helper must be backed by the real OwnerCoordinator, all-path PR fencing/reservation, durable OwnerRecord CAS and old-owner I/O drain.
2. The metadata usage snapshot must come from authoritative runtime counters.
3. BMPOOL03 still needs to be connected to per-AG Bitmap/Mapping WAL so Data extent allocation, zeroing, mapping publication and extent-map updates share one crash-recoverable transaction/reconciliation protocol.
4. BMPOOL02 remains on the existing fixed-layout path; there is no online in-place migration.
5. Full two-node SAN qualification and hardware power-loss testing remain mandatory before production enablement.
