# P3-3.12.3.2 — Pool-backed Volume Runtime backend

This slice adds `PoolVolumeRuntimeBackend`, a concrete composition layer for
Pool-backed metadata objects. It deliberately accepts a small set of platform
adapters instead of importing `internal/metadata` or `internal/wal` into
`internal/metastore`; those packages already depend on metastore through the
allocator/WAL path, and importing them here would create a Go package cycle.

## Runtime path

1. Open the configured metadata device.
2. For RW, acquire the configured fenced Owner Lease. The provider contract
   requires old-owner SAN fencing to complete and be verified before it returns.
3. Read the BMPOOL02 Pool Superblock and the selected Volume Descriptor pair.
4. Locate the Volume's AG from the descriptor and replay that AG's WAL through
   the supplied cluster-safe committer factory.
5. Reopen the descriptor after recovery; construct Pool-backed Store,
   ReaderTable (the reserved per-Volume Reader Table range), and
   PersistentArena.
6. Require a live-page enumerator. It must return every page reachable from
   the B+Tree root except the root itself; PersistentArena adds the root and
   durable Retire Queue pages while rebuilding allocation state.
7. For RW, publish the lease epoch through `Store.AdvanceOwnerEpoch`.
8. For RO, acquire the per-slot sanlock lease, register local SCSI PR keys on
   all paths, persist the Reader record, and run periodic durable heartbeats.
   Lease or heartbeat loss invokes the mandatory fail-stop callback.
9. Build the production Reader Recovery Controller by default. It uses the
   same distributed sanlock locker for Reader Set coordination and expired
   Reader Slot probes, the configured SAN fencer, and the metadata I/O drain
   barrier before Retire Queue collection.
10. Request admission, stop, drain and metadata close are delegated to
    mandatory platform hooks.

## Required adapter contracts

- `OpenPoolSuperblock`: validate and read both BMPOOL02 copies.
- `CommitterForAG`: return a cluster-safe WAL committer for the descriptor's AG.
- `RecoverAG`: replay that committer while RW Owner Lease is held.
- `Owner.AcquireFencedOwner`: acquire the exclusive Owner resource and finish
  old-owner PREEMPT AND ABORT/verification on every SAN path before success.
- `LivePages`: enumerate the complete live B+Tree page graph; omission is
  unsafe and can cause live metadata to be reused.
- `OnReaderLeaseLost`: synchronously suspend/fail-stop the local data path.
- `DrainMetadataIO`: prove local metadata I/O has drained; a successful SCSI
  PR operation alone is not an I/O drain proof.

The backend constructor rejects a missing distributed locker, a NoopFencer,
a non-sanlock Reader Lease Probe, a mismatched Reader Probe locker, and a
missing automatic-recovery heartbeat timeout.

## Deliberate limits

The v2 Volume Descriptor does not persist previous Owner NodeID/BootID.
Therefore the Owner provider remains a required deployment adapter and must
obtain the prior owner identity from the cluster's authoritative ownership
record. This backend does not guess it.

The package boundary also avoids a dependency cycle: callers supply the
BMPOOL02 reader, AG committer factory, and WAL recovery operation. A daemon
can wire these to `metadata.OpenStoreDevice` and `wal.SharedCommitter`.

The heartbeat worker is tied to the opened runtime session, not the short-lived
activation context. Deactivation cancels and joins it before unregistering
local PR keys and closing the durable Reader slot.

This is an integration layer with explicit safety contracts, not proof of
production SAN correctness. Real multipath PR, sanlock lease-loss, DM
suspend/drain, and power-loss recovery qualification remain required.
