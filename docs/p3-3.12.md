# P3-3.12 — Linux Block Device Backend 与 bm-meta 固定 LBA 入口

## 本阶段交付

### 1. Linux BlockDevice

新增 `internal/device/block_linux.go`，实现现有 `device.Device` 接口：

- 只接受 Linux block device；通过打开后的 FD 执行 `fstat` 检查，拒绝普通文件。
- 通过 `BLKGETSIZE64` 获取真实容量，不使用 `stat.Size()`。
- 通过 `BLKSSZGET` 获取 logical sector size，并校验扇区大小是 512..65536 范围内的 2 次幂。
- 支持只读 / 读写打开。
- 可选 `O_EXCL`，用于同一主机内避免另一个本地 opener 同时打开该 block device。
- `ReadAt/WriteAt` 检查容量边界；`Sync` 使用文件描述符 `fsync`，向 Linux block layer 提交 flush。
- 关闭后拒绝 I/O；容量、关闭与 I/O 状态使用互斥锁保护。

不使用 `O_DIRECT`。元数据层以 4 KiB 页面访问，普通 block-device buffered I/O 可由内核 block layer 完成；持久化边界由 `Sync` 的 fsync 实现。当前接口尚未实现 FUA 写入，也没有做 SAN 控制器掉电保护认证。

### 2. bm-meta 命令入口

旧 JSON demo 被移动到显式的 `demo` 子命令，避免默认路径让人误以为使用了 SAN 元数据设备。

只读检查：

```bash
bm-meta inspect \
  --device /dev/mapper/mpath-meta \
  --volume-id volume-0001
```

格式化（破坏性操作）：

```bash
bm-meta format \
  --device /dev/mapper/mpath-meta \
  --volume-id volume-0001 \
  --arena-start 2 \
  --arena-pages 100000 \
  --lifecycle-start 100002 \
  --lifecycle-pages 16 \
  --confirm-format
```

页数必须按目标 LUN 的真实容量和布局计算，以上数字仅为命令格式示例，不能直接复制到生产设备。所有偏移单位均为 4 KiB page。Arena 与 lifecycle 区域不得重叠。

`format` 要求显式 `--confirm-format`，以读写模式和本地 `O_EXCL` 打开设备，并初始化双 Superblock 与 lifecycle pages。格式化前仍必须由运维流程确保该 LUN 没有被任何其他节点使用；本地 `O_EXCL` 不是跨节点锁，也不能代替 sanlock Owner Lease / fencing。

`inspect` 以只读模式打开设备，检查双 Superblock 并刷新到最新有效 generation。它不会获取 Reader Slot Lease，不会注册 SCSI PR，也不应被当成可供数据路径使用的 RO Volume Runtime。

JSON 报告包含设备路径、容量、logical sector size、只读状态和 metastore Superblock。

### 3. 自动化检查

- Linux block backend 的单元测试确保普通文件和不存在的路径被拒绝。
- bm-meta 命令测试确保格式化必须显式确认、lifecycle 区域必须给出、inspect 必须指定设备和 Volume ID。
- CI 执行 `go test ./...`、`go test -race ./...` 和 `go vet ./...`。

## 重要发现：现有两套 Superblock 几何尚未统一

在把设备接入生产 WAL 前，发现仓库当前存在两种同样使用 LBA 0 / LBA 1、magic 同为 `BMMETA01`，但二进制编码不兼容的 Superblock：

1. `internal/metastore/store.go` 的 metastore Superblock：版本字段为 uint16，Volume ID 在 64..127 字节，CRC32C 位于 4 KiB page 最后 4 字节。
2. `internal/format/superblock.go` 的 Pool/AG Superblock：版本字段为 uint32，Pool UUID 和 Pool/AG/WAL 区域几何字段不同，CRC32C 位于 offset 160。

`internal/wal.Journal` 需要第二种 `format.Superblock` 提供 AG WAL / checkpoint 几何；P3 Reader Table、Arena 和 Volume Runtime 当前使用第一种 `metastore.Superblock`。二者不能同时写到同一设备的前两个 4 KiB page，也不能通过简单类型转换互相替代。

因此本阶段的 `bm-meta format/inspect` 明确只操作当前 `metastore.Store` 格式；没有擅自构造假的 `format.Superblock`，也没有把 `SharedCommitter` 接到不匹配的磁盘布局上。否则设备格式化后启动 WAL 可能把不相关字段解释成 WAL offset / size，属于不可接受的数据破坏风险。

## 尚未完成的生产 daemon 接入

P3-3.12 交付真实 Linux 块设备 I/O 和安全的固定 LBA format/inspect 入口，但尚未提供完整的生产 `VolumeRuntimeBackend`。继续生产化前必须完成：

1. **Superblock 统一**：决定一个权威 Pool/Volume 元数据布局，把 Volume identity、Pool/AG geometry、WAL/checkpoint、Arena、Reader Table 和 Root Descriptor 放入可验证且不重叠的磁盘格式；提供迁移/版本兼容策略。
2. **WAL 接线**：在统一布局上打开 AG Journal，持有分布式 Owner/AG Lease 后执行 recovery，再把 `SharedCommitter` 注入 Store、ReaderTable 和 PersistentArena。
3. **sanlock provisioning**：实现 lockspace 加入检查、Owner/AG/Reader Slot 资源名配置与 helper 可执行性检查。
4. **SCSI PR**：配置可信 initiator key，注册本节点 key，并对每条 multipath path 验证 PREEMPT AND ABORT。
5. **DM 请求入口**：对接 target 的 request admission、fail-stop callback 和全局 metadata I/O drain。
6. **daemon 生命周期**：将上述组件构造成 `VolumeRuntimeBackend`，接入 `VolumeRuntimeManager`；缺少任一生产依赖时拒绝启动，不允许 fallback 到 demo backend。

在上述工作完成前，`bm-meta inspect` 只用于离线检查，`bm-meta format` 只用于经过外部 fencing/quiesce 的初始化流程；两者都不等价于生产读写 Daemon。真实 SAN LUN、多路径、掉电与多节点竞争测试仍需在目标环境完成。


## 后续格式统一更新

P3-3.12.1 已将 Pool Superblock 升级为 BMPOOL02 v2，并将 Volume Descriptor 升级为 BMDVOL02 v2。`bm-meta format/inspect` 现操作 Pool 层格式；每个 Volume 的 Arena / Root / Lifecycle 几何由 Node Table Descriptor 表达。详细字段、格式化顺序、兼容性和未完成的 Store 迁移见 [docs/p3-3.12.1.md](p3-3.12.1.md)。

注意：旧 `metastore.Store` 尚未迁移到 Pool-backed Volume Store，不能在 BMPOOL02 Pool 设备上使用。当前完成的是统一磁盘结构定义、Volume Descriptor 初始化/读取、Allocator codec 迁移和 WAL 对 Pool Superblock 的保护，不代表 COW B+Tree / Reader Table / Retire Queue 已全部接入新格式。


## P3-3.12.2 Pool-backed Store 更新

后续 P3-3.12.1 已统一 Pool / Volume 磁盘格式，P3-3.12.2 又完成了 Pool-backed Volume Store：COW B+Tree、Arena、Lifecycle、Reader Generation 和 Retire Queue 可通过 Node Table 的 BMDVOL02 Descriptor 定位到 Volume 私有 extents；新 Root Descriptor 作为 WAL 最后一个 after-image 发布。新增 `bm-meta volume-init` / `volume-inspect`。详细设计与限制见 [docs/p3-3.12.2.md](p3-3.12.2.md)。

旧版本文档中关于 `bm-meta format/inspect` 操作独立 BMMETA01 Volume 的描述属于 P3-3.12 初始实现，已被 P3-3.12.1/3.12.2 的 BMPOOL02/BMDVOL02 布局取代。不要在 BMPOOL02 设备上使用 legacy `metastore.Format/Open`。
