# P4-1.2.5.5 — Single-device bounded region foundation

BlockMesh uses one backing block device for both metadata and user data. The
backing device may be a multipath map, a single-path iSCSI disk, or a local
block device. The device is opened once by the component that owns its
lifecycle. Metadata and data components receive non-owning bounded views.

`internal/device.Range` implements that view:

- view offsets are relative to the view; parent offsets are absolute;
- reads and writes cannot escape the configured byte range;
- an out-of-range write is rejected before any parent I/O (no partial write);
- reads crossing the end follow `io.ReaderAt` semantics and return the
  in-range prefix with `io.EOF`;
- Sync is forwarded to the common parent device;
- closing a view does not close the shared parent.

The intended composition is:

```go
backing, err := device.OpenBlockDevice(path, true, true)
if err != nil { return err }
metadataView, err := device.NewRange(backing, metadataStart, metadataLength)
if err != nil { return err }
dataView, err := device.NewRange(backing, dataStart, dataLength)
if err != nil { return err }
// The owner closes metadataView/dataView as needed, then closes backing once.
```

This commit establishes the single-device I/O boundary only. It does not yet
change the on-disk Pool format, fixed geometry constants, allocator wiring,
DM table ABI, or provide online metadata expansion. Those are subsequent
steps. In particular, a Range must not be used to disguise overlapping
metadata/data regions: layout validation must establish non-overlap before
constructing either view.
