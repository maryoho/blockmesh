# P4-1.2 — Fixed-width UAPI and queue contract

## Scope and implementation boundary

This increment defines the byte-level Linux 5.15 kernel/userspace ABI: fixed-width little-endian records, ioctl numbers, mmap offsets, bounded ring sizing, request correlation, and generation-bound cancellation/reset semantics. The C header is kernel-facing; internal/uapi is the Go reference encoder/decoder and queue-lifecycle contract. One node-wide character device is shared by all DM Targets; each Target owns a distinct Queue Context.

This increment implements Go codecs and validation for GET_ABI, SETUP_QUEUE and CANCEL payloads, mmap layout calculation, and a concurrency-safe completion correlator. It does NOT register a character device, map ring pages, submit DM BIOs through the queue, or connect the metadata service to SAN-backed metadata. The DM target therefore remains the existing linear remapper. This is still an ABI/control-protocol foundation, not a live data-path transport.

## Wire records

| Record | Bytes | Purpose |
|---|---:|---|
| Ring control | 64 | Shared indices, ring size and generation |
| Request | 128 | Identity, operation, logical range and idempotency key |
| Completion | 64 | Request correlation, status and payload reference |
| Mapping | 24 | Logical/physical block run |
| Setup ioctl | 80 | Ring order, generation and mmap offsets |
| Cancel ioctl | 40 | Request ID and queue generation |
| ABI info | 64 | Version, record sizes, limits and feature bits |

All multibyte fields are little-endian. UUIDs are binary 16-byte values. Version and exact size are present in request/completion records. Reserved fields must be zero. Logical and physical block numbers use the allocator's 4MiB block unit. Mapping payload length must equal mapping_count * 24; non-success completions cannot carry payload.

## Queue layout

One service process owns the exclusive node-wide device session. Ring size is 1 << ring_order, where 4 <= ring_order <= 10. The five page-aligned offsets below are queue-local offsets. For a shared `/dev/blockmesh` FD, userspace encodes each mmap byte offset as `(queue_id << 44) | queue_local_offset`; queue IDs are monotonic, non-zero 19-bit values and are never reused during a module lifetime. The low 44 bits carry the local offset, and the high 19 bits select the queue. This gives each queue a disjoint 16TiB virtual-offset window without allocating that address space. The five queue-local offsets are:

| Offset | Region | Producer | Consumer |
|---:|---|---|---|
| 0x00000000 | Request control | Kernel | Service |
| 0x00010000 | Request ring | Kernel | Service |
| 0x00040000 | Completion control | Service | Kernel |
| 0x00050000 | Completion ring | Service | Kernel |
| 0x00060000 | Mapping payload slots | Service | Kernel |

For every supported ring order, Layout() verifies that the request ring ends before completion control and completion ring ends before payload. Payload reserves MaxBatch mapping records per ring slot. Total mmap size is page aligned. Rings are SPSC. Producer writes the entry/payload then publishes tail with release ordering. Consumer loads tail with acquire ordering, reads the entry, then publishes head after consumption. Kernel owns request indices; userspace owns completion indices. The other side must never write an index it does not own. Shared indices require smp_load_acquire/smp_store_release in kernel and matching atomics in userspace.

## ioctl lifecycle

1. GET_ABI negotiates version, record sizes and limits.
2. The service opens `/dev/blockmesh` once (exclusive opener), enumerates Target-created queues with NEXT_QUEUE, and calls SETUP_QUEUE for each Queue ID. The kernel attaches the service session and returns queue ID, offsets, generation and limits. Userspace validates every returned offset against Layout() plus the queue-ID encoding before mmap.
3. Service mmaps all regions, validates dimensions, then drains requests.
4. CANCEL is best-effort for (generation, request_id). It is idempotent; a late completion cannot satisfy another request.
5. RESET_QUEUE revokes the old generation, terminates outstanding work, and requires a new setup/handshake.
6. Service FD close detaches all queues, advances their generations, invalidates outstanding requests and wakes waiters. Target removal destroys only that Target's queue; VMA references defer memory release. Teardown must not wait indefinitely for userspace.

Request correlation key is (queue_generation, request_id). Correlator rejects duplicate in-flight IDs, ignores completions for cancelled requests, stale generations, unknown IDs and duplicate completions. Reset clears all pending IDs and requires a different non-zero generation. IDs must not wrap within a generation.

## Identity and failure behavior

Each request carries VolumeID, NodeID and BootID UUIDs. Mutations and FLUSH require OwnerEpoch; allocation/discard also require a 128-bit idempotency key. RO lookups carry ReaderEpoch and RootGeneration; RW lookups carry OwnerEpoch. Queue generation is transport fencing, not a replacement for OwnerEpoch, sanlock, or SCSI PR fencing.

Disconnect, timeout, malformed completion, queue exhaustion, or generation mismatch are fail-closed. The target must not reuse a cache generation after service restart and must never fall back to linear I/O. A stale OwnerEpoch response cannot reopen the DM write gate.

## Validation boundary

Go tests cover serialization, fixed sizes, reserved fields, identity/epoch/idempotency requirements, completion payload constraints, mmap bounds at every ring order, setup-offset validation, and completion correlation across cancellation/reset. They do not validate C compiler layout, kernel mmap lifetime, SMP ordering, Linux 5.15 DM teardown, or SAN fencing. The kernel endpoint patch must add sizeof/offsetof static assertions and compile against supported 5.15 kernel headers before ABI qualification. P4-1.2.1 adds the global misc character device, Target-owned Queue Context registry, exclusive service FD, GET_ABI/NEXT_QUEUE/SETUP_QUEUE/RESET_QUEUE handlers, queue-scoped mmap, VMA references, registry-change EPOLLPRI, and aggregate request EPOLLIN scan. A service restart detaches and drops the old queue memory object; old VMAs retain their old pages and cannot alias the new generation's mapping. Request production from DM BIOs, completion consumption, cancellation registry, and metadata-service transport remain deferred. The device currently provides queue lifecycle and shared-memory mapping primitives, not a functional BIO data path.
