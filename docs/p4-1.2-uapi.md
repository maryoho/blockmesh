# P4-1.2 — Fixed-width UAPI and queue contract

## Scope and implementation boundary

This increment defines the byte-level Linux 5.15 kernel/userspace ABI: fixed-width little-endian records, ioctl numbers, mmap offsets, bounded ring sizing, request correlation, and generation-bound cancellation/reset semantics. The C header is kernel-facing; internal/uapi is the Go reference encoder/decoder.

This commit does NOT register a character device, map ring pages, submit DM BIOs through the queue, or connect the metadata service to SAN-backed metadata. The DM target therefore remains the existing linear remapper. This is the ABI foundation, not a live data-path transport.

## Wire records

| Record | Bytes | Purpose |
|---|---:|---|
| Ring control | 64 | Shared indices, ring size and generation |
| Request | 128 | Identity, operation, logical range and idempotency key |
| Completion | 64 | Request correlation, status and payload reference |
| Mapping | 24 | Logical/physical block run |

All multibyte fields are little-endian. UUIDs are binary 16-byte values. Version and exact size are present in request/completion records. Reserved fields must be zero. Logical and physical block numbers use the allocator's 4MiB block unit. Mapping payload length must equal mapping_count * 24; non-success completions cannot carry payload.

## Queue layout

One service process owns the per-target endpoint. Ring size is 1 << ring_order, where 4 <= ring_order <= 10. The five page-aligned mmap offsets are:

| Offset | Region | Producer | Consumer |
|---:|---|---|---|
| 0x00000000 | Request control | Kernel | Service |
| 0x00010000 | Request ring | Kernel | Service |
| 0x00020000 | Completion control | Service | Kernel |
| 0x00030000 | Completion ring | Service | Kernel |
| 0x00040000 | Mapping payload slots | Service | Kernel |

Rings are SPSC. Producer writes the entry/payload then publishes tail with release ordering. Consumer loads tail with acquire ordering, reads the entry, then publishes head after consumption. Kernel owns request indices; userspace owns completion indices. The other side must never write an index it does not own. Shared indices require smp_load_acquire/smp_store_release in kernel and matching atomics in userspace.

## ioctl lifecycle

1. GET_ABI negotiates version, record sizes and limits.
2. The service opens the endpoint and calls SETUP_QUEUE once. Kernel allocates bounded rings and returns offsets, generation and limits.
3. Service mmaps all regions, validates dimensions, then drains requests.
4. CANCEL is best-effort for (generation, request_id). It is idempotent; a late completion cannot satisfy another request.
5. RESET_QUEUE revokes the old generation, terminates outstanding work, and requires a new setup/handshake.
6. Endpoint close or target removal closes admission and terminates outstanding work exactly once. Teardown must not wait indefinitely for userspace.

Request correlation key is (queue_generation, request_id). Unknown, duplicate, cancelled, or stale-generation completions are discarded. IDs must not wrap within a generation; reset creates a new generation.

## Identity and failure behavior

Each request carries VolumeID, NodeID and BootID UUIDs. Mutations and FLUSH require OwnerEpoch; allocation/discard also require a 128-bit idempotency key. RO lookups carry ReaderEpoch and RootGeneration; RW lookups carry OwnerEpoch. Queue generation is transport fencing, not a replacement for OwnerEpoch, sanlock, or SCSI PR fencing.

Disconnect, timeout, malformed completion, queue exhaustion, or generation mismatch are fail-closed. The target must not reuse a cache generation after service restart and must never fall back to linear I/O. A stale OwnerEpoch response cannot reopen the DM write gate.

## Validation boundary

Go tests cover serialization, fixed sizes, reserved fields, identity/epoch/idempotency requirements, and completion payload constraints. They do not validate C compiler layout, kernel mmap lifetime, SMP ordering, Linux 5.15 DM teardown, or SAN fencing. The kernel endpoint patch must add sizeof/offsetof static assertions and compile against supported 5.15 kernel headers before ABI qualification. poll/eventfd notification and actual char-device lifecycle are also deferred to that patch.
