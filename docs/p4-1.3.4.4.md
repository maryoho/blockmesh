# P4-1.3.4.4 — Kernel Pending BIO 与 Metadata Service Cancellation Handshake

## 协议目标

取消是协作请求，不是内核立即结束 BIO 的命令。内核收到取消请求后仍保留 Pending BIO；Metadata Service 取消对应的 Go context，并继续发布唯一的最终 completion。completion 才是 BIO 的终态依据。

## 身份

取消使用三元组 (QueueID, QueueGeneration, RequestID)。队列代际不匹配返回 ESTALE；BIO 已经被 completion 消费或不再 pending 时返回 EALREADY；重复取消返回 EALREADY。UAPI 仍为 40 字节，QueueID 使用原 cancel 结构的第二个 u32 槽位，结构大小与 ioctl 编码不变。ABI feature bit 2 表示支持该握手。

## 状态与竞争规则

1. Kernel BM_IOC_CANCEL 在队列锁下查找 Pending BIO，标记 cancel_requested，但不释放 BIO。
2. Metadata Service 对匹配 generation 的活跃 request 调用 context cancel。
3. Processor 必须遵守 context；事务层必须在 WAL commit 边界判断结果。未提交可返回 CodeRetry；已经提交必须返回 CodeOK（以及原操作结果）。
4. Kernel 收到 CodeRetry 时以 BLK_STS_AGAIN 结束 BIO；收到 CodeOK 时正常执行原映射/IO完成路径，即使之前已收到取消请求。
5. Cancel ioctl 先于 completion 消费成功时只代表取消请求已登记，不代表 BIO 已结束。若 completion 先被消费，取消返回 EALREADY，不能覆盖已完成结果。

## 安全边界

- 不在 ioctl 中调用 bio_io_error，也不直接从内核取消正在执行的元数据事务。
- 不因取消而更换原请求的幂等键；重试必须复用原 request identity/idempotency key。
- queue generation 是防止旧服务进程取消新队列请求的 fencing token。
- CodeOK 优先于取消标志，避免 WAL 已提交但 BIO 报错导致重复分配。
- 当前实现提供内核 pending 登记与 service context cancellation 的闭环；Processor/allocator 仍须正确实现 commit-aware cancellation，不能把任意 context error 无条件映射成未提交。
