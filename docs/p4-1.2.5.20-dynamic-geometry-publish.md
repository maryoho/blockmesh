# P4-1.2.5.20 — Dynamic Geometry Rebuild and Dual-Superblock Publication

Adds an online geometry update planner and publication path for BMPOOL03.
It supports metadata-view growth and DataView growth within the existing
final AG while preserving all current metadata region offsets.

When DataBytes grows, newly valid bits were previously marked as allocated
padding. `PlanDynamicBitmapGrow` verifies those bits are still reserved,
clears them, updates the AG descriptor sequence and bitmap CRC, and emits
redo after-images. The caller commits these through the dynamic AG WAL before
the new geometry is published.

Superblock publication writes the inactive/older copy and Syncs, then mirrors
the new generation to the previous active copy and Syncs. A crash between
copies leaves at least one valid new copy; a crash before the first copy leaves
the old geometry authoritative. `ViewGeneration` must advance with the
Bootstrap Extent Map generation.

Important current boundary: increasing AGCount changes the sizes and offsets
of per-AG WAL/Bitmap regions and would move Mapping/Checkpoint. This stage
fails closed with ErrDynamicGeometryRequiresMigration instead of silently
relocating existing B+Tree/Volume metadata. Supporting additional AGs requires
pre-reserved AG capacity or an explicit metadata-layout migration.
