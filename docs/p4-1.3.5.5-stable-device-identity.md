# P4-1.3.5.5 — Stable SAN device identity

Pool-scoped sanlock resources must be derived from the shared device identity,
not from a host-local path such as `/dev/sdb` or `/dev/mapper/mpatha`.

The Linux device helper `device.StableBlockIdentity` resolves the block
device's major/minor through sysfs and uses the following identity sources:

1. Device Mapper multipath `dm/uuid` when it is prefixed with `mpath-`.
2. SCSI `device/wwid` or the block device's `wwid`.
3. `device/serial` as a final stable identifier.

The returned value is normalized to lowercase. The helper intentionally
returns an error when sysfs exposes no stable identity; it never falls back
to the input device path or major/minor because those values can differ
between nodes.

This is the prerequisite for P4-1.3.5 Pool creation to derive the same
sanlock resource name on every initiator while allowing the operator to pass
a multipath mapper, direct iSCSI path, or local block device.

Tests cover multipath WWID preference, direct SCSI WWID, missing identity,
and missing sysfs device. These are unit tests; target-host validation is
still required for the supported HBA, multipath and local-disk combinations.
