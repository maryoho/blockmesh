# P4-1.2.5.19 — DataView and Dynamic PoolAllocator Integration

The dynamic PoolAllocator path now consumes a BMPOOL03 DynamicSuperblock and
BMDVOL03 Volume Descriptor, plans bitmap allocation using the persisted AG
geometry, and zeros the supplied DataView directly. No DataStartSector offset
is applied on this path.

The physical block ID returned by the dynamic bitmap planner is
`AGStartBlock + localBit` in DataView coordinates. That same ID is used
for the B+Tree Mapping value and the byte offset `physicalID * 4MiB` in
DataView. The metadata transaction includes bitmap pages, the external
idempotency record, PersistentArena lifecycle pages and the final BMDVOL03
root descriptor through DynamicSharedCommitter.

An integration test uses one parent device with separate Bootstrap,
Metadata and Data extents, verifies block zero is zeroed before publication,
checks the bitmap and Mapping, and retries the same idempotency key.

The shared-committer lock resource and Owner Lease are supplied by the caller;
this code does not replace the SAN fencing/OwnerCoordinator protocol.
