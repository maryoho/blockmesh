# P4-1.2.5.16 — BMPOOL03 Dynamic WAL Journal

Adds `OpenDynamicJournal` using `DynamicSuperblock.Geometry`:
AG count, segment base, and segment capacity are all runtime geometry values.
The append-only redo path uses the same versioned intent/commit record codec as
the BMPOOL02 journal, with the required ordering: Intent Sync, Commit Sync,
after-image application, final Sync. Open performs recovery before returning.

Each AG owns exactly one segment of `WALSegmentBytes`. Updates must be
4KiB aligned, remain inside MetadataView, avoid the Bootstrap format marker and
all WAL segments, and cannot overwrite the superblock copies. Torn trailing
records are ignored; malformed complete records are treated as corruption.

This stage intentionally has no log reclamation or checkpoint rotation.
A segment eventually returns `ErrJournalFull`; P4-1.2.5.17 adds the
dynamic dual-descriptor checkpoint protocol. The caller remains responsible
for AG locking and fenced Owner authorization.
