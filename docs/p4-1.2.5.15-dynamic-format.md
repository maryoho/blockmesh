# P4-1.2.5.15 — BMPOOL03 Bitmap Initialization and Format Publication

`FormatDynamicPool` initializes every AG bitmap and descriptor before
publishing either DynamicSuperblock copy. It uses a durable format marker at
MetadataView offset 8KiB (outside the planned metadata regions):

1. Require blank superblock copies and marker, then write marker and Sync.
2. Initialize each padded bitmap. All valid data bits start free; padding bits
   beyond the final AG's valid block count are set allocated.
3. Initialize each AG descriptor with sequence 1 and CRC32C over the complete
   padded bitmap; Sync all bitmap/descriptor writes.
4. Publish superblock copy A and Sync, then copy B and Sync.
5. Clear the format marker and Sync.

If interrupted while the marker remains, open refuses to expose the pool.
`RecoverDynamicFormat` accepts only the matching Pool UUID, generation,
view generation and geometry, then safely repeats initialization/publication.
The formatter rejects an unmarked nonblank device and never overwrites a
different published superblock.

The caller must hold the exclusive fenced SAN Owner lease across formatting;
this package-level API cannot itself establish SCSI PR fencing or sanlock
ownership. It is a format primitive, not proof of production SAN crash safety.
