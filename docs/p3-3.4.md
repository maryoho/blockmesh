# P3-3.4: atomic Bitmap / Mapping / Volume Descriptor transaction

`allocator.AllocateOneTxn` writes the AG Bitmap Descriptor, affected Bitmap page, Mapping page, and inactive Volume Descriptor as one per-AG redo-WAL transaction. The Volume Descriptor is the final after-image and publishes the new Mapping root, Volume Sequence, Bitmap Sequence, and Owner Epoch.

Each Volume Descriptor uses two adjacent 4 KiB slots in the 1 MiB Node Table reserved region (128 pairs maximum). The higher-generation valid slot is active; each transaction writes the inactive slot. The descriptor format is `BMDVOL01`, version 1, little-endian, CRC32C.

The transaction is limited to one AG and one Volume. Cross-AG work must be split into independent transactions; no 2PC is provided.

Important limitations:
- Legacy `AllocateOne` remains available but does not publish a Volume Descriptor. New transactional callers must use `AllocateOneTxn`.
- The caller assigns a stable descriptor pair index and supplies the current fenced owner epoch. The current Lease interface has no epoch accessor, so the package can compare the supplied epoch with the durable descriptor but cannot independently validate it with the lease service.
- The Mapping builder must provide a complete 4 KiB page image. A general Mapping B+Tree encoder is not yet integrated.
- Persistent retire queue, reader generations, SAN fencing, cache invalidation, and crash-safe physical block reclamation remain outstanding.
- Pool `format.Superblock` and B+Tree `metastore.Superblock` remain separate formats; this path uses the Pool fixed-LBA layout only.
