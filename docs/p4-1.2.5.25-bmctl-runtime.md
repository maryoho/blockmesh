# P4-1.2.5.25 — bmctl Pool Runtime Orchestration

Pool configuration lives at /etc/blockmesh/pools/<pool-id>.json. Mutating operations require device_path, lockspace, lock_device, lock_offset_bytes and owner_lease_helper.

## Commands

- bmctl pool format --pool pool-001 --confirm-format — legacy Bootstrap format.
- bmctl pool dynamic-format --pool pool-001 --confirm-format — BMPOOL03 format, Reserved allocator initialization and initial Volume publication.
- bmctl pool dynamic-status --pool pool-001 — read-only BMPOOL03 and Bootstrap geometry status.
- bmctl pool dynamic-recover --pool pool-001 — fenced WAL replay and Reserved allocator reconciliation.
- bmctl pool rescan --pool pool-001 — discover larger parent-LUN capacity and publish Free extents.
- bmctl pool metadata-expand --pool pool-001 — calculate Metadata target from fresh metadata usage telemetry, allocate Metadata extents, publish Geometry, reconcile Reserved allocator and grow the initial Volume Arena.
- bmctl pool data-expand --pool pool-001 — calculate Data target from fresh Data usage telemetry, allocate 4MiB-aligned Data extents, initialize newly exposed Bitmap/AG metadata and publish the dual Superblock.
- bmctl pool metadata-expand-status --pool pool-001 — read-only Bootstrap extent status.

## Usage telemetry

Metadata expansion uses metadata_usage_file; Data expansion uses data_usage_file. Each file contains used_bytes, growth_bytes and observed_at (RFC3339). The maximum age is configured independently by metadata_usage_max_age_seconds and data_usage_max_age_seconds; each defaults to 3600 seconds.

The CLI never accepts a target Metadata/Data capacity. It computes the target from observed use plus forecast growth and 30% headroom, aligned to 1GiB Metadata extents or 4MiB Data extents. If Data capacity already satisfies the forecast, data-expand is a no-op.

## Safety and recovery

Mutating commands hold the helper-provided fenced Owner lease and distributed Bootstrap sanlock lock. Bootstrap Extent Map publication precedes view reopening; MetadataView and DataView are then opened from the same generation. Dynamic WAL commit and Superblock publication are performed only after OwnerEpoch admission checks.

If Data extents are committed to Bootstrap but BMPOOL03 Geometry publication is interrupted, the additional extents remain reserved but are not exposed to allocators until data-expand is rerun or dynamic-recover is used. The old Superblock remains authoritative until the new generation is published.

These commands provide orchestration; real SAN power-loss, all-path PR fencing and DM inflight drain qualification still require the platform-specific Owner lease helper and external test environment.
