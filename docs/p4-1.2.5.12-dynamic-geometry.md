# P4-1.2.5.12 — BMPOOL03 Dynamic Pool Geometry

This stage introduces a checked geometry planner for the BMPOOL03 logical
MetadataView and DataView. It deliberately does not change the BMPOOL02
superblock codec or its fixed 100TiB/1TiB-AG layout.

## Geometry rules

- Data capacity is expressed in 4MiB allocation blocks.
- AG count is ceil(DataBlocks / AGSizeBlocks).
- The final AG records its actual block count; no tail capacity is silently
  discarded and no fake full AG is exposed.
- Each AG bitmap has ceil(AGBlocks/8) bytes, rounded up to 4KiB pages.
- Each AG bitmap region is one 4KiB descriptor page followed by padded bitmap
  pages.
- WAL is reserved per AG; Node Table, WAL, Bitmap, Mapping and Checkpoint
  regions are laid out with checked arithmetic and page alignment.
- MetadataBytes is the logical size of MetadataView, excluding bootstrap
  bytes. DataBytes is the logical size of DataView, not the parent LUN size.

## Scope and compatibility

PlanDynamicGeometry is a pure planner and does not format media. It does not
yet encode a BMPOOL03 superblock, initialize bitmap descriptors, or switch the
existing BMPOOL02 allocator. Those are subsequent steps. Existing BMPOOL02
constants and NewSuperblock remain unchanged, preserving old on-disk layout.

The next stage will version and persist this geometry in a BMPOOL03 superblock,
then make bitmap allocation and WAL addressing consume persisted per-AG
dimensions rather than legacy package constants.
