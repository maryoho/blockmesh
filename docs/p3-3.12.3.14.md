# P3-3.12.3.14 — Owner crash injection and real-SAN recovery acceptance

## Deliverables

- `cmd/bm-owner-crash-qualify`: read-only metadata evidence capture and
  pre/post recovery verifier.
- `scripts/owner-crash-qualification.sh`: captures metadata and SCSI PR /
  multipath / sanlock / DM evidence on each node, then performs closed-loop
  verification.
- `scripts/inject-owner-process-crash.sh`: opt-in SIGKILL of a verified
  BlockMesh systemd main process on a disposable test Volume. It does not
  power off a host, alter PR state, or write metadata.

## Build

```bash
go build -o bm-owner-crash-qualify ./cmd/bm-owner-crash-qualify
go build -o bm-san-qualify ./cmd/bm-san-qualify
```

Run the metadata snapshot tool as root or with read access to the multipath
metadata device. It opens the device read-only and does not acquire sanlock,
modify OwnerRecord, write descriptors, or change DM/PR state.

## Capture evidence on both nodes

On each node, pass the metadata multipath map and the complete explicit list
of its component paths. The component path list must be identical to the
currently verified `multipath -ll` topology.

```bash
scripts/owner-crash-qualification.sh capture \
  ./bm-owner-crash-qualify ./bm-san-qualify \
  /dev/mapper/mpath-meta /dev/sda,/dev/sdb \
  volume-uuid 3 node-a "$(cat /proc/sys/kernel/random/boot_id)" \
  evidence/node-a-before
```

Repeat on Node B with its local device/path names and identity. Store evidence
outside the SAN LUN being tested, preferably on an independent evidence host.
The output files are mode 0600, use exclusive creation, and include SHA-256
sidecars. Never edit captured JSON; create a new prefix for every capture.

The metadata snapshot records both raw descriptor-page hashes and decoded
validity/generation/OwnerEpoch, both OwnerRecord-page hashes and basic
generation/epoch/CRC evidence, and the selected decoded OwnerRecord identity.
The verifier selects the highest-generation valid descriptor and compares its
OwnerEpoch with the durable OwnerRecord Epoch.

## Process crash injection

First capture baseline evidence and confirm the test Volume ID, WWID and
component path inventory. Then, on Node A only, run from an out-of-band
administrative session:

```bash
export BLOCKMESH_TEST_LUN=volume-uuid
sudo --preserve-env=BLOCKMESH_TEST_LUN \
  scripts/inject-owner-process-crash.sh blockmesh-owner.service volume-uuid \
  I_UNDERSTAND_THIS_KILLS_BLOCKMESH_ON_A_TEST_NODE
```

The script checks the exact environment Volume ID, systemd unit MainPID,
ExecStart and process executable/cmdline before sending SIGKILL to the main
process. It does not restart the service. Capture post-crash evidence before
any restart or manual cleanup. This is a destructive test action: run only on
an isolated disposable test LUN with an approved maintenance window and
out-of-band recovery.

For host power-loss, HBA reset, switch isolation and array controller failure,
use the lab's separately reviewed power/network/array controls. This project
does not automate those operations.

## Closed-loop acceptance

After Node B has completed its normal takeover and its DM write gate is open,
capture a fresh post-recovery snapshot on Node B. Copy the before/after
evidence prefixes to one verifier host, then run:

```bash
scripts/owner-crash-qualification.sh verify \
  ./bm-owner-crash-qualify ./bm-san-qualify \
  evidence/node-a-before evidence/node-b-after \
  0xOLD_OWNER_KEY 0xNEW_OWNER_KEY 6 node-b NEW_BOOT_ID
```

PASS requires all of the following:

1. Before/after Pool UUID, Volume ID and Volume index match.
2. Post-recovery OwnerRecord NodeID/BootID match Node B.
3. New OwnerRecord Epoch is strictly greater than every valid pre-fault
   descriptor and OwnerRecord Epoch.
4. Highest-generation valid BMDVOL02 descriptor OwnerEpoch equals the
   selected SAN OwnerRecord Epoch.
5. Old Owner PR key is absent on every explicitly listed component path.
6. New Owner reservation holder and PR type match on every listed path.

Any unreadable path, incomplete multipath coverage, WWID disagreement,
unparseable PR output, missing OwnerRecord, invalid descriptor or Epoch
mismatch is FAIL/INCONCLUSIVE. Keep DM admission closed.

## Crash-point matrix

Run one fault per test iteration and retain a separate evidence prefix:

| Injection point | Injection mechanism | Expected recovery |
|---|---|---|
| Owner process killed before OwnerRecord CAS | SIGKILL service main process | previous durable identity remains; new Owner fences it and advances epoch |
| Owner process killed after OwnerRecord Sync, before PR RESERVE | lab-controlled pause/kill at instrumented checkpoint | new Owner fences the just-published identity, then advances epoch |
| PR RESERVE response lost | array/transport fault injection in lab | new Owner fences ambiguous identity; no rollback of OwnerRecord |
| sanlock helper/daemon loss | controlled process/service fault | old DM path fail-stops; new Owner waits for exclusive resource and fences old identity |
| One component path unavailable | controlled path isolation | no RW activation until every required path is verified or explicitly restored |
| Host power loss | out-of-band PDU | persistent OwnerRecord and descriptor recover; old initiator cannot write |
| Array controller failover / cache fault | array test procedure | flush durability and APTPL/PR behavior meet array guarantees |

The current SIGKILL helper covers only the service-process crash. The remaining
fault points require explicit runtime checkpoint instrumentation or external
lab controls; they are not falsely reported as automated.

## What constitutes full production PASS

The script's PASS is a metadata/PR evidence sub-result, not an overall
production safety certification. Full PASS additionally requires independent
evidence of:

- sanlock exclusive Owner resource on the new node and absence on the old;
- SCSI PREEMPT AND ABORT semantics and old initiator write exclusion;
- old local DM queue closed and inflight metadata I/O drained;
- no write admission before WAL recovery and durable descriptor publication;
- application data checksum/sequence continuity after takeover;
- actual Linux 5.15.131 kernel, HBA, multipath and array qualification;
- power-loss durability across controller failover and protected cache flush.

GitHub CI can validate Go logic and script syntax, but cannot prove physical SAN
durability or real two-host fencing. Never reconnect an unfenced old node to
the live test LUN merely to demonstrate that its writes fail.
