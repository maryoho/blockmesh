# P4-1.2.5.7 — Pool Device Geometry and Format Compatibility

BMPOOL03 stores physical device capacity, logical sector size, metadata capacity, and extent-map generation in its checksummed Bootstrap record. The geometry is not inferred from BMPOOL02's fixed 100TiB/16GiB constants.

`DetectFormat` distinguishes BMPOOL02 and BMPOOL03 by their format magic. A damaged BMPOOL02 Superblock is still recognized as legacy by magic and cannot fall through to the BMPOOL03 formatter. `OpenPoolSpace` deliberately refuses to reinterpret a BMPOOL02 Pool; old Pools continue using their existing reader and layout.

Device growth is observed through the block-device rescan hook and persisted as Free extents. Shrink is rejected. Multipath, single-path iSCSI, and local block devices use the same `device.Device` interface; the device's logical sector size is recorded during BMPOOL03 initialization.

The new format is an explicit format boundary, not an in-place BMPOOL02 migration. No existing Pool data is relocated.
