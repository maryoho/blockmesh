# P4-1.3.2.1 — BMPOOL03 Dynamic Runtime Backend

## Implemented

Commit `27f974cab1ca7fb364cf2233f941fab2348429f5` adds `internal/dynamicruntime`.

The backend is intentionally separate from `internal/metastore.PoolVolumeRuntimeBackend`, which remains the BMPOOL02 runtime implementation.

### OpenReadWrite sequence

1. Validate the requested Volume/Node/Boot identity and require RW mode.
2. Require a live P3 Owner lease carrying durable OwnerRecord identity, verified SCSI PR reservation, previous-owner fencing and old-owner I/O drain proof.
3. Open the parent LUN through the configured device opener.
4. Recover/open BMPOOL03 Bootstrap and bind its future updates to the distributed locker and current Owner lease.
5. Open MetadataView and DataView from one Bootstrap Extent Map snapshot and validate their generation.
6. Open the BMPOOL03 Dynamic Superblock pair; verify Pool UUID, ViewGeneration and geometry against the Bootstrap and views.
7. Open the BMDVOL03 Volume Descriptor selected by VolumeIndex.
8. Construct one distributed DynamicSharedCommitter per AG and recover every AG WAL while guarded by the P3 Owner lease.
9. Publish the newly acquired OwnerEpoch through the Volume's AG WAL.
10. Replace the lease-only WAL guards with guards that also reread the authoritative BMDVOL03 OwnerEpoch.
11. Open the persistent COW B+Tree and PersistentArena, resolving idempotency external pages.
12. Construct the BMPOOL03 DynamicPoolAllocator against the DataView.

The runtime owns the parent LUN, both logical views and the Owner lease. The logical views are non-owning and do not close the shared parent device.

## Safety properties

- BMPOOL02 is not accepted by this backend.
- Metadata and Data views originate from the same parent LUN and Bootstrap generation.
- Pool UUID and view-generation mismatches fail activation.
- A local/non-distributed locker is rejected.
- Owner fencing proof is required before opening the LUN.
- All AG WALs are recovered before OwnerEpoch publication and mutable B+Tree open.
- Every WAL operation is guarded by the live Owner lease; after publication it also checks the durable descriptor OwnerEpoch.
- Failure cleanup closes views, lease and parent device.
- No DM queue admission is performed in this substage.

## Tests

`backend_test.go` covers configuration rejection, missing Owner proof and RW/RO mode separation. The full file-backed BMPOOL03 activation, WAL crash/reopen, COW and discard acceptance matrix remains part of P4-1.3.2.2–P4-1.3.2.x.

## Explicitly not complete

This substage does not yet implement:
- RO Reader Lease / Reader Generation activation.
- A DynamicVolumeRuntimeManager lifecycle wrapper.
- DM OwnerEpoch gate and queue admission.
- Owner lease-loss watcher and synchronous fail-stop/drain integration.
- COW overwrite, discard retirement and request-facing mutation dispatch.

Those remain required before P4-1.3.2 can be called complete.
