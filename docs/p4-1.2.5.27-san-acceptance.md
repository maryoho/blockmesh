# P4-1.2.5.27 — Real SAN Multi-Node Fault-Injection Acceptance

## Scope and safety boundary

This phase provides read-only evidence collectors, offline evidence verifiers, process-crash test helpers and a repeatable two-node qualification runbook. It does not remotely power off hosts, change array PR state, or inject path failures automatically. Those operations require an independently controlled lab PDU/STONITH/array test environment and an operator-approved maintenance window.

Passing GitHub CI proves software tests and the Linux 5.15 module build; it does not prove a real SAN array, multipath stack or power-loss behavior.

## Evidence tools

- bm-owner-san-agent capture collects a node's Pool/Volume identity, BootID, multipath map, explicit component-path inventory, SCSI PR registrations/reservation, DM status and OwnerRecord/OwnerEpoch snapshot.
- bm-owner-san-agent verify-pair compares two node bundles and requires both to observe the same SAN identity and durable Owner state.
- bm-san-qualify collect records read-only multipath, dmsetup, sanlock and all-component-path SCSI PR evidence.
- bm-san-qualify verify-fenced requires the previous Owner key to be absent on every inspected path.
- bm-san-qualify verify-reservation checks the new reservation holder and type on every inspected path.
- bm-owner-crash-qualify snapshot-dynamic and verify-dynamic capture and compare BMPOOL03 Superblock, BMDVOL03 descriptor and SAN OwnerRecord generations.
- scripts/owner-san-two-node-capture.sh captures baseline bundles from both nodes.
- scripts/dynamic-owner-crash-qualification.sh captures before/after Owner state and verifies OwnerEpoch and PR evidence. It explicitly does not power off a node.

Evidence files are created exclusively, retained for audit, and written with restrictive permissions. The collector requires an explicit component-path list and refuses to infer incomplete multipath coverage.

## Lab topology prerequisites

1. Two independent Linux nodes with unique NodeID and BootID, the same SAN LUN, and the same multipath WWID.
2. A list of every active and standby component path for the LUN on both nodes.
3. A qualified array SCSI PR implementation and a tested PR type/key mapping.
4. A platform Owner lease helper, durable SAN OwnerRecord store, old-owner I/O drain barrier and DM OwnerEpoch gate.
5. Independent PDU/STONITH control with an auditable power-off and power-on record.
6. A disposable Pool/Volume with known data patterns and checksums; never use the first run against production data.
7. Synchronized clocks and a dedicated evidence directory with enough free space.

## Required test matrix

| ID | Fault / operation | Required result |
|---|---|---|
| SAN-01 | Baseline capture on both nodes | Same Pool UUID, Volume ID, WWID and consistent OwnerRecord/OwnerEpoch |
| SAN-02 | Concurrent Owner acquisition | Exactly one node obtains the exclusive Owner lease and verified PR reservation |
| SAN-03 | Old Owner process termination | New Owner does not proceed until all-path fencing and old I/O drain succeed |
| SAN-04 | Abrupt old-node power loss via external PDU | New Owner fences old registrations, increments OwnerEpoch and recovers WAL before RW admission |
| SAN-05 | One component path unavailable during takeover | Takeover fails closed; no partial-path success is accepted |
| SAN-06 | All SAN paths lost | No new Owner admission; no stale writer is admitted; recovery resumes only after path and PR state are revalidated |
| SAN-07 | Crash after durable WAL Commit | Reopen replays committed after-images; Bitmap, Mapping, Idempotency and Volume root agree |
| SAN-08 | Crash during Checkpoint bank switch | Highest valid descriptor/bank is selected; committed transactions are neither lost nor replayed twice |
| SAN-09 | Crash during AG activation | Old AGCount remains authoritative until all new AG metadata is durable and a new Superblock copy is published |
| SAN-10 | Crash during Metadata/Data expansion | Bootstrap and BMPOOL03 generations are reconciled; unexposed extents are not allocatable |
| SAN-11 | Stale OwnerEpoch writes after takeover | DM gate rejects old epoch and records the rejection |
| SAN-12 | Volume release with one path not fenced | Reserved metadata pages are not freed or reused |

## Per-test evidence procedure

1. Capture the before-state from both nodes with scripts/owner-san-two-node-capture.sh.
2. Record the exact fault action, operator, PDU/STONITH request ID, start/end times and array event identifiers separately from the software evidence.
3. Execute one fault at a time. Do not combine path loss, power loss and metadata expansion in a single run.
4. Restore the lab topology and wait for multipath path discovery before any recovery command.
5. Capture after-state from both nodes. Run dynamic-owner-crash-qualification.sh verify for takeover cases and the bm-san-qualify verifiers for path-level PR state.
6. Run read/write checksum verification, inspect DM gate events and confirm no old OwnerEpoch request reached the backing LUN.
7. Preserve raw command output, JSON evidence, checksums, array logs, PDU/STONITH audit logs and kernel logs as one immutable test bundle.

## Pass criteria

- Every configured component path is accounted for on both nodes.
- Previous Owner PR key is absent on all paths before takeover completes.
- New Owner reservation holder/type matches on all paths.
- OwnerRecord and BMDVOL03 OwnerEpoch agree and increase monotonically.
- Old-owner local I/O is drained or fenced before RW admission.
- WAL recovery completes before the new DM RW gate opens.
- All test data checksums match after recovery.
- Every injected crash has a documented recovery outcome; no ambiguous state is silently treated as success.

## What CI can and cannot certify

GitHub Actions runs go test ./..., go test -race ./..., go vet ./... and builds the DM target/global character device against Linux 5.15 headers. Unit and simulated crash tests are CI-verifiable. SAN-01 through SAN-12 require the real lab; their results must be attached as operator-generated evidence. Until those bundles exist and pass review, the real-SAN qualification status is NOT RUN, not PASS.
