# P4-1.2.5.11 — Logical Metadata/Data views over one Pool device

BMPOOL03 now exposes two immutable logical address-space snapshots from one Extent Map generation:

- MetadataView concatenates every Metadata extent while excluding the Bootstrap reservation [0, BootstrapSize). Bootstrap records, Extent Map slots and Bootstrap WAL remain accessible only through the parent Pool device.
- DataView concatenates fragmented Data extents into a zero-based logical data device.
- OpenViews returns both views and the Bootstrap generation from one lock-protected snapshot. Callers must reopen the views after Rescan, Metadata expansion or Data extent allocation.

AllocateDataExtents reserves 4MiB-aligned physical extents as Data and commits the Extent Map before exposing the new DataView. This is Pool-capacity provisioning, not per-block allocation. Individual 4MiB block ownership remains in the per-AG Bitmap transaction; AllocateZeroPublish continues to zero and sync a selected logical Data block before its Bitmap/Mapping/idempotency WAL publication.

This establishes the correct address translation boundary for a future dynamic Pool metadata backend. It does NOT yet make the existing BMPOOL02 format.Superblock, fixed AG bitmap geometry, Volume Descriptor layout or PoolAllocator accept arbitrary BMPOOL03 capacities. Those fixed-geometry consumers must be generalized and versioned before BMPOOL03 can host the existing runtime. Do not point a BMPOOL02 runtime at these views and assume compatibility.

Tests cover fragmented Metadata and Data translation, Bootstrap exclusion, same-parent-LUN I/O, durable Data extent-map publication/reopen, and alignment rejection.
