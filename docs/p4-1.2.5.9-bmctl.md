# P4-1.2.5.9 — bmctl Pool operations

Pool configuration is stored at /etc/blockmesh/pools/<pool-id>.json. Required fields:
- device_path: multipath, single-path iSCSI, or local block device
- lockspace, lock_device, lock_offset_bytes: unique sanlock resource location
- owner_lease_helper: helper implementing the fenced Owner lease contract in owner-lease-helper.md

For format, also set volume_slots and optionally logical_sector_bytes. If omitted, bmctl detects the logical sector size from the block device.

For metadata expansion, configure metadata_usage_file with a fresh JSON snapshot containing used_bytes, growth_bytes and observed_at (RFC3339). metadata_usage_max_age_seconds defaults to 3600. These values describe measured/forecast Metadata usage; the CLI never accepts a target capacity.

Commands:
- bmctl pool format --pool pool-001 --confirm-format
- bmctl pool rescan --pool pool-001
- bmctl pool metadata-expand --pool pool-001
- bmctl pool metadata-expand-status --pool pool-001

Mutating commands hold the helper-provided fenced Owner lease and the distributed Bootstrap sanlock lock. Status is read-only. The metadata service must provide authoritative usage telemetry; the CLI does not fabricate it.
