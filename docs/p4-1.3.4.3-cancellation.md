# P4-1.3.4.3 — In-flight request cancellation

## Queue-local cancellation registry

Each active request is registered by the compound identity `(QueueGeneration, RequestID)` with its request-scoped cancel function. `QueueMemory.Cancel` and `Device.CancelRequest` only cancel an active Processor invocation in the currently mapped generation. A stale generation, unknown request, or already completed request returns false and has no effect.

The registry entry is removed after Processor returns. The cancellation context is always created with `context.WithCancel`, including when the request deadline is disabled; a positive configured deadline wraps that context with `context.WithTimeout`.

## Commit race contract

Cancellation is cooperative. It is not a rollback primitive and does not remove a kernel pending BIO. The allocator must check cancellation before the durable WAL commit boundary. If cancellation wins before commit, Processor returns a retryable cancellation result. If WAL commit wins, Processor returns the committed result even if cancellation is requested immediately afterward. The durable idempotency record remains the recovery authority.

The Device protects its queue map and mapped memory lifetime with an RWMutex. Queue draining holds a read lock while touching a mapping; reconciliation and unmapping require the write lock. This prevents a concurrent cancellation or queue generation reconciliation from dereferencing an unmapped region.

## Current boundary

The in-process cancellation path is implemented and tested. The kernel `BM_IOC_CANCEL` command is still intentionally unsupported in this increment: an ioctl that merely marks a pending BIO canceled could incorrectly fail a BIO whose metadata transaction committed concurrently. Kernel-side cancellation will only be enabled once the ABI defines the complete handshake and committed-result precedence.

## Tests

- Active request cancellation propagates to Processor context.
- Stale QueueGeneration cannot cancel a current request.
- Completed requests cannot be canceled.
- Cancellation registry entries are removed after processing.
- Existing request deadline and parent shutdown cancellation tests remain in place.
