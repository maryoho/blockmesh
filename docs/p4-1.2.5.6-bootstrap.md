# P4-1.2.5.6 — Dynamic Bootstrap Metadata

This increment introduces a separately versioned BMPOOL03 bootstrap format. It does not reinterpret or modify BMPOOL02 metadata offsets.

- Two 4KiB Bootstrap record slots live at byte offsets 0 and 4096.
- Two alternating extent-map slots live inside the 4MiB bootstrap reservation.
- An update writes and syncs the inactive extent-map slot first, then writes and syncs the inactive Bootstrap record. Recovery selects the highest generation whose referenced map validates.
- Device capacity is recorded independently from metadata capacity. Rescan adds newly visible bytes as Free; it does not silently turn them into Metadata.
- Metadata growth is selected by the allocator from usage/growth observations; the caller does not specify a target capacity.
- The single parent device is used for both Metadata and Data physical extents.

This is a format foundation, not yet a production-online migration of BMPOOL02. BMPOOL02 is rejected by the BMPOOL03 formatter and remains on its existing fixed-layout implementation. Cluster owner fencing and the existing AG WAL integration for BMPOOL03 are follow-on requirements before online multi-node use.
