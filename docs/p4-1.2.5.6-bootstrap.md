# P4-1.2.5.6 — Persistent Bootstrap Metadata

The dynamic Pool bootstrap is versioned independently as BMPOOL03. Its fixed Bootstrap reservation is 8MiB:
- Two 4KiB Bootstrap records at offsets 0 and 4KiB.
- Two alternating 2MiB Extent Map slots after the records.
- Two 4KiB Bootstrap WAL pages after the Extent Map slots.
- Remaining reserved bytes are held for format growth.

The record contains Pool UUID, generation, actual device bytes, Bootstrap bytes, total Metadata bytes, Extent Map root offset/length/generation, logical sector size, fenced OwnerEpoch and CRC32C. The extent map must cover the entire device without gaps or overlaps.

The inactive Extent Map is written and synced before its Bootstrap root is published. The redo Intent/Commit protocol protects that publication. Recovery rejects corrupt committed roots and ignores an after-image without a matching Commit.

The physical allocator classifies byte ranges as Metadata, Data or Free, and extent views are bounded ranges over the same parent device. BMPOOL02 is not rewritten or migrated by this code.
