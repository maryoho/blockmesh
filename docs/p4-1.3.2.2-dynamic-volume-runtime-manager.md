# P4-1.3.2.2 — BMPOOL03 DynamicVolumeRuntimeManager

## Scope

This stage adds the lifecycle manager around the BMPOOL03 dynamicruntime.Runtime. It is separate from the BMPOOL02 metastore.VolumeRuntimeManager and does not route BMPOOL03 activation through the fixed-LBA runtime backend.

## Runtime contracts

- RW activation obtains a proof-bearing lease from a P3 OwnerCoordinator adapter. The lease must expose a live Lost() channel and pass the existing backend's SCSI PR, previous-owner fencing, I/O-drain and OwnerRecord checks.
- Backend.OpenReadWrite consumes the Owner lease. It owns cleanup on failed activation; on success the returned Runtime owns the lease.
- RO activation is supplied through an explicit OpenReadOnly adapter. The adapter must open BMPOOL03 views from one Bootstrap generation and join a durable Reader Table / sanlock Reader session. The manager does not invent Reader slots or lease identities.
- A RO session must expose Heartbeat and CloseDrained; failed heartbeat invokes the same synchronous DM fail-stop contract.
- RequestGate.EnableRequestsGuarded must serialize the supplied health check with actual DM queue admission. FailStop must synchronously suspend/fence the local data path before returning.

## Lifecycle

1. Validate Volume / Node / Boot identity and mode-specific ReaderEpoch.
2. Serialize operations for the same Volume while allowing different Volumes to activate independently.
3. Acquire P3 Owner lease for RW, or join Reader session for RO.
4. Open the BMPOOL03 Runtime using the mode-specific opener.
5. Start Owner-loss supervision or RO Reader heartbeat supervision.
6. Enable DM requests only through the guarded RequestGate.
7. On deactivate/shutdown: stop admission -> drain requests -> stop and join lease supervision -> close drained Reader session (RO) -> close Runtime views and Owner lease -> release parent LUN.

A failed Stop/Drain or failed fail-stop keeps the Runtime registered and pinned. Callers may retry Deactivate after the platform has repaired the unsafe boundary. The manager never silently reacquires a lost Owner or Reader lease.

## Tests added

- RW activation and idempotent repeated activation.
- RW conflicting identity rejection.
- RO Reader heartbeat and drained close lifecycle.
- Lease-loss fail-stop failure pins Runtime resources and preserves the lease-lost state for operator recovery.

## Integration boundary / not yet complete

This stage supplies lifecycle orchestration and explicit adapter contracts. It does not yet provide a production DM RequestGate implementation or a BMPOOL03 RO opener. Those must be wired to the actual DM target admission, suspend/drain primitives, dynamic Reader Table, and generation pinning before claiming end-to-end production activation. P4-1.3.2.3 should implement those adapters and acceptance tests; do not use no-op gates or test-only lockers in production configuration.
