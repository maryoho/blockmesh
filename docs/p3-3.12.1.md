# P3-3.12.1 — Unified Pool / Volume Disk Layout

## Pool Superblock v2

- LBA 0 and LBA 1 are the only redundant Pool Superblock locations.
- Magic is `BMPOOL02`, version 2; CRC32C is at byte offset 160.
- Pool UUID, capacity, AG geometry, and WAL/Bitmap/Mapping/Checkpoint extents are stored here.
- Decoder validates alignment, bounds, overlap, and minimum region sizes.
- Pool metadata capacity is now 16 GiB. The previous 8 GiB setting was smaller than the sum of the configured WAL, Bitmap, Mapping, and Checkpoint regions.
- Legacy `BMMETA01` Pool pages are not accepted by the v2 decoder.

## Volume Descriptor v2

- Each Volume owns one two-page slot in the Pool Node Table.
- Magic is `BMDVOL02`, version 2; each page has a CRC32C at its final four bytes.
- The descriptor contains Volume identity, AG, Owner Epoch, generation, Mapping Root Offset, Arena extent, B+Tree Root Page, Mapping Sequence, and Lifecycle extent.
- `internal/format.VolumeDescriptor` is the canonical codec. Allocator uses a type alias to that codec.
- `metadata.InitVolume` assigns a deterministic, page-aligned bootstrap extent from Pool Reserved, zeros lifecycle pages before publishing either descriptor copy, then writes and syncs the two redundant copies.
- `metadata.ReadVolumeDescriptor` selects the newest valid copy and validates that Arena and Lifecycle extents remain inside Pool Reserved.

## Formatting

`bm-meta format` now initializes the Pool, not an individual Volume. It requires a real Linux block device, local O_EXCL, and explicit confirmation. It invalidates old Pool Superblocks, clears Node Table, WAL and Checkpoint regions, initializes AG Bitmaps, and publishes BMPOOL02 copies last. The caller must still quiesce and fence all other nodes; O_EXCL is not distributed fencing.

`bm-meta inspect` reads the Pool Superblock pair. The JSON demo remains separate and is not production-safe.

## WAL protection and compatibility

On a device containing a valid BMPOOL02 Superblock, Journal rejects any after-image targeting LBA 0/1. Legacy metastore root after-images are only accepted on images that do not contain a valid Pool Superblock, preserving old isolated unit tests; they are not compatible with a formatted Pool device.

## Remaining integration work

The old `metastore.Store` still owns its historical standalone Volume Superblock implementation. Its COW B+Tree, Persistent Arena, Reader Table, Retire Queue, and Volume Runtime must still be migrated to a Pool-backed Store that loads the Node Table descriptor and publishes the inactive descriptor as the final WAL after-image. Do not use the old Store on BMPOOL02 devices. A production daemon, SAN fencing, and hardware recovery qualification are also not delivered by this phase.
